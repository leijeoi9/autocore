## 三、Phase 2.1：ISO-TP 传输层 (ISO 15765-2)

### 为什么需要 ISO-TP？

CAN 2.0 一帧最多传 8 字节。诊断请求经常超过 8 字节（如读取 VIN 码 17 字节）。ISO-TP 负责将长报文拆成多帧发送，接收端重组。

### 新增文件

| 文件 | 大小 | 说明 |
|------|------|------|
| `bsw/diag/iso_tp/include/iso_tp.h` | 4KB | 接口定义 |
| `bsw/diag/iso_tp/src/iso_tp.c` | 12KB | 完整实现 |

### 四种帧类型

| 类型 | 缩写 | 用途 | 最大数据 |
|------|------|------|----------|
| 单帧 | SF | 短报文一帧发完 | 7 字节 |
| 首帧 | FF | 声明总长度 + 前 6 字节 | 总长度 ≤ 4095 |
| 流控帧 | FC | 接收方控制发送节奏 | 3 字节固定 |
| 连续帧 | CF | 后续数据帧 | 7 字节/帧 |

### 多帧传输过程

```
发送方                       接收方
  │── FF (总长度=300) ──────→│  首帧
  │←── FC (继续发) ──────────│  流控帧
  │── CF (序号=1) ──────────→│
  │── CF (序号=2) ──────────→│
  │── ...                    │
  │── CF (最后) ────────────→│  接收完毕
```

## 四、Phase 2.2：UDS 诊断服务 (ISO 14229)

### 什么是 UDS？

UDS 是汽车行业的标准诊断协议。诊断仪通过 CAN/以太网向 ECU 发请求，ECU 回复响应。

### 新增文件

| 文件 | 说明 |
|------|------|
| `bsw/diag/uds/include/uds.h` | SID/NRC/DID 定义 + 外部接口 |
| `bsw/diag/uds/src/uds_core.c` | 18KB，6 个服务的完整实现 |

### 实现的 6 个服务

| SID | 服务名 | 做了什么 |
|-----|--------|---------|
| **0x10** | 诊断会话控制 | 切换默认/编程/扩展会话。只有扩展/编程会话才能写数据 |
| **0x22** | 读取数据 (DID) | 通过 DID 读发动机转速(F100)、车速(F101)、温度(F102)、VIN(F190)、版本号 |
| **0x2E** | 写入数据 (DID) | 写 VIN 等参数（需要扩展/编程会话） |
| **0x27** | 安全访问 | **种子-密钥两步验证**（面试重点）：发 2701 请求种子 → ECU 返回 4 字节种子 → 客户端计算密钥发回（seed ^ 0x12345678）→ ECU 验证解锁。3 次失败锁定 10 秒 |
| **0x19** | 读取故障码 | 报告 DTC 数量或 DTC 列表 |
| **0x14** | 清除故障码 | 清空所有 DTC |

### UDS 基本通信模型

```
诊断仪                          ECU
  │── [0x22] [F1] [00] ──────→│  读取发动机转速
  │←── [0x62] [F1] [00] [数据] ─│  肯定响应
  │                              │
  │── [0x27] [01] ────────────→│  请求种子
  │←── [0x67] [01] [4字节种子] ─│  种子
  │── [0x27] [02] [密钥] ─────→│  发送密钥
  │←── [0x67] [02] ────────────│  解锁成功
```

## 六、Phase 3.2：DoIP (ISO 13400)

### 什么是 DoIP？

DoIP 是通过以太网做 UDS 诊断。比 CAN 快 100 倍，支持车辆自动发现。

### 新增文件

| 文件 | 说明 |
|------|------|
| `bsw/tcp_ip/doip/include/doip.h` | DoIP 协议定义 |
| `bsw/tcp_ip/doip/src/doip.c` | 12KB，完整 DoIP 服务器 |

### DoIP 功能

| 功能 | 说明 |
|------|------|
| 车辆发现 | UDP 广播，回复 VIN + 逻辑地址 |
| 路由激活 | TCP 连接后需要激活才能收发诊断消息 |
| 诊断消息 | 通过 TCP 封装 UDS 报文 |

## 九、常见面试问题

### Q：AUTOSAR 分几层？你的项目是怎么分的？
> 四层：应用层(ASW) → RTE → 基础软件层(BSW) → 微控制器抽象层(MCAL)
> 我们的项目：app/ → rte/ → bsw/ → bsw/mcal/

### Q：RTE 的作用是什么？
> 解耦应用层和底层硬件。应用层通过 Rte_Read/Rte_Write 读写数据，不知道数据是从 CAN 来的还是诊断来的。

### Q：ISO-TP 解决了什么问题？
> CAN 一帧只有 8 字节。ISO-TP 通过 SF/FF/FC/CF 四种帧类型实现长报文的分段传输和重组。

### Q：UDS 的 0x27 安全访问怎么工作的？
> 两步：客户端请求种子(0x27 01)，ECU 返回随机数；客户端发送密钥种子(0x27 02)，ECU 验证。3 次失败锁定 10 秒。

### Q：DoIP 和 CAN 诊断有什么区别？
> CAN 带宽只有 500kbps，DoIP 使用以太网 100Mbps，适合固件升级等大数据量场景。DoIP 还支持车辆自动发现（UDP 广播 VIN）。
